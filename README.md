# PLECS → Simulink translations (ideal switches)

Simulink versions of the three PLECS models in `plecs_source/` (from `PLECS_08_10_26.zip`),
built for fast evaluation of the control strategies:

| PLECS model | Simulink model (generated) | What it is |
|---|---|---|
| `DAB FPGA.plecs` | `simulink/dab/dab_fpga.slx` | 700 V → 250 V dual active bridge, CLLC-style series caps, FPGA phase-shift PWM, Vo PI |
| `Class D Rev B.plecs` | `simulink/classd/classd_revb.slx` | 3 interleaved full bridges (6 half bridges) driving a load, 3 current PI loops at 2 MHz |
| `SixSwitch.plecs` | `simulink/sixswitch/sixswitch.slx` | 3-phase 2-level grid converter (active rectifier), LCL filter, PLL + decoupled dq control, SVPWM |

Only base **Simulink** is needed (no Simscape / Specialized Power Systems).

## Building the models

The `.slx` files are generated by script (the repository holds the generator rather than
binaries):

```matlab
cd simulink
build_all          % writes dab/dab_fpga.slx, classd/classd_revb.slx, sixswitch/sixswitch.slx
```

`smoke_test` (same folder) builds each model, compiles it and runs a short simulation, and
prints the first error if any — the quickest check of a fresh MATLAB install. Notes for
picking the work up in another Claude Code session are in `CLAUDE.md`.

Each model's `InitFcn` runs its parameter script (`dab_params.m`, `classd_params.m`,
`sixswitch_params.m`), which holds the PLECS initialisation commands plus the translation
settings. Change parameters there, not in the blocks. The positions of the PLECS manual
switches are the `sel_*` variables in the same files.

## How the models are built

* **Power stage = ideal switches.** Each converter is one MATLAB Function block holding the
  circuit equations (`*_plant.m`, readable on their own) plus an Integrator for the states.
  Switches have zero on-resistance and switch instantly. During dead time a leg is clamped by
  the ideal anti-parallel diode selected by the sign of its current. That current sign comes
  from a Relational Operator on the state vector, so the solver gets a zero-crossing event
  when a diode current reverses.
* **Switching instants are located exactly.** Every gate comes from a Relational Operator
  on smooth signals (carriers or `sin()` phase signals) with zero-crossing detection. That
  includes the dead time: a turn-on delay of `g = (m > c)` is generated as
  `(m > c(t)) AND (m > c(t − td))`. The solver is variable-step `ode23tb`, so it takes
  small steps only around switching events.
* **Control = ordinary Simulink blocks** laid out like the PLECS schematics (same block names
  where possible): PID Controller / Discrete PID Controller, Zero-Order Hold, Fcn, Switch,
  Relay, …. PLECS-only library blocks are rebuilt from basic blocks (`simulink/common/p2s_*.m`):
  Periodic Average, Moving Average, RMS Value, Ramp, and the Manual Signal Switch (a Switch
  driven by a `sel_*` constant).
* A **Memory block** on each plant's measurement output breaks the algebraic loop that would
  otherwise run gate → ESR drop in the measured voltage → control → gate. It delays the
  measurements by one solver step, which is negligible.

### Left out (not needed for control evaluation)

Thermal networks, heat sinks, switch loss calculators and loss/efficiency displays based on
device data; snubbers, Coss, gate resistors, the 55 pF transformer inter-winding capacitance,
82 nF film capacitors and the 0.4 µH in series with the SixSwitch damping resistors (all
switching transients); THD meters; the small-signal perturbation/response blocks, AC sweep
and multitone analyses; the PLECS scripts (parameter sweeps). Also not translated: the two
filter-analysis test benches (`Current Feedback Filter.plecs`, `SixSwitch Filter Testing.plecs`),
which are frequency-response setups rather than converter models.

## Model notes

### DAB (`dab_fpga.slx`)

* Circuit as drawn in PLECS, with the transformer configuration "Electrical":
  * external primary leakage `Llkp` and series cap `Crp`;
  * the 1.3 mH inductor `Llk1` across the transformer terminals;
  * transformer-internal leakages `Lp`, `Ls` and `Lm`, winding resistances `Rp`, `Rs`, ratio 11:4;
  * external secondary leakage `Llks` and series cap `Crs`;
  * input `Vin` with `R1` and `Cin`, and output `Co` ∥ `Cdc`, each behind its ESR.

  The coupled inductor currents are solved with a constant inverse inductance matrix.
* Load: the PLECS current source, drawing `P/Vref` from the output (16 kW at 250 V).
* Control path as selected in PLECS:
  * `Vref − Vo` → Periodic Average (2 switching periods) → PI (kp 0.125, ki 0.002, initial
    0.25, limits ±0.49) → ×0.5 = φ;
  * Dp/Ds scheduling (TPS slope/intercept, Relay/Switch logic, `Force`), with
    α = (1 − D)/2;
  * the FPGA-style **Phase Shift PWM** with 100 ns turn-on delay.

  The unused "Triple Phase Shift Modulator" alternative is not translated. The C-Script
  alternative for αP/αS is (`dab_alpha_cscript.m`, `sel_alphaP/S = 2`).
* **Worth knowing:** the transformer block gets `Lp = Ls = Llk = 13 µH`, *on top of* the
  external `Llkp = Llk/2` and `Llks`. The primary-referred series inductance is therefore
  ≈ 118 µH, not 13 µH. With that inductance the bridge can only move about 3.5 kW at
  700 V / 250 V, so Vo sags under the 16 kW load (≈ 3.3 kW at φ ≈ 0.2 in the check run).
  This is a property of the PLECS circuit as saved, not of the translation. If the internal
  leakages were meant to be zero, set `dab_tx.Lp = 0; dab_tx.Ls = 0;` in `dab_params.m`.

### Class D (`classd_revb.slx`)

* Six half bridges on one bus:
  * A/B/C drive the output P through their leg inductors, D/E/F drive N;
  * the load sits between P and N;
  * bus = the 18 mF bank with its ESR (the half-bridge 10 µF capacitors are lumped in), fed
    by the AC_DC block (100 A current source + 400 V zener + diode, i.e. a 400 V supply
    with a 100 A limit).
* Load options (switch `S4`, `sel_load`):
  1. RC network + 26 µH;
  2. 0.711 Ω + 10 V/20 Hz source;
  3. `RField` 0.19 Ω (`LField` is commented out in PLECS), the saved position.
* Control as in PLECS:
  * demand: 4 Hz → 10 kHz sine sweep × 10 (or the 567 Hz sine, pulse, DC or shock waveform
    via the `sel_*` switches);
  * `iPID` "Three PID's": PI kp 0.005, ki 10, 2 MHz, ±1 on demand/3 − (Ip − In)/2 per leg pair;
  * 3-state PWM at 33.3 kHz, carriers interleaved by T/3, 500 ns turn-on delay;
  * the voltage-feedback PID path is included (`sel_ipid = 2`).
* **Changed default:** the PLECS model is saved with "Class D Inductors" = *No Inductors*
  (200 nH on leg A and 0.2 nH on the other five legs) and *No Filter*. With ideal switches,
  three interleaved legs in parallel with nothing between them produce unlimited circulating
  current. So the default here is the *No Mutual Inductance* configuration, 75 µH per leg
  (`Lleg` in `classd_params.m`). Set `Lleg = [200e-9; 0.2e-9*ones(5,1)]` to reproduce the
  saved state. Even with 75 µH, uncoupled interleaved legs circulate ≈ ±25 A of ripple
  between legs. That is physical, and it is why the library also offers coupled-inductor
  configurations.

### SixSwitch (`sixswitch.slx`)

* Converter (dead time "off" in PLECS):
  * per phase: 400 µH, then a damped shunt branch (4.7 Ω + 2.2 µF to N), then 35 µH, then
    0.4 Ω, then the grid source;
  * the grid amplitude ramps up over 0.2 ms;
  * DC link: 60 µF + 4.2 mΩ;
  * the DC side floats relative to the grid neutral;
  * load: `Ro = Vdc_ref²/P(t)` with the 100 W → 18 kW ramp from 50 ms (or the 440 Ω +
    pulsed 100 Ω loads, `sel_load = 1`).
* Control as in PLECS:
  * DC voltage: Moving Average (100 µs) → PI (0.25 / 160, 100 kHz, −32…40 A) → id*;
  * sensing: Vph/Iph sampled at 32 kHz → PLL → abc>dq;
  * current loops: d-axis PI (3.5 / 125) with ωL decoupling, voltage reference
    `vdq − [Vd*; Vq*]` → αβ;
  * modulation: SVPWM (min/max injection), single update at the carrier minimum, 100 kHz.
* **Worth knowing:** in the saved PLECS model the q-axis "Manual Switch" selects the
  constant −1.85 V instead of the q-axis PI output, so iq is not closed-loop controlled
  (`sel_q = 2` connects the PI). This is reproduced as saved. In the check run it lets iq
  drift to about −60 A within 25 ms, while Vdc still settles at 700 V. With `sel_q = 2`
  the model holds Vdc at 700 ± 1.5 V and iq ≈ 0 from the start.
* The PLECS "Three-Phase PLL" library block is replaced by an SRF-PLL. It drives the
  q-axis voltage of the same abc>dq transform to zero, with a PI at ωn = 2π·25 rad/s,
  ζ = 0.707 (`pll.*`). θ starts at 0 like the PLECS block, which means it starts ≈ π/2
  away from the grid angle. The model therefore shows a start-up transient until the PLL
  locks. As saved (q-axis open loop), Vdc swings to ≈ 965 V in the first 4 ms and settles
  at ≈ 700 V by 17 ms.

## Assumptions made where the PLECS file does not say

* **Manual Signal Switch / Manual Switch position k selects input k** (the upper input is 1).
  This is consistent with every model: for example the DAB `Vout Target`, and the SixSwitch
  voltage controller and `Ro` load. All of them are `sel_*` variables, so they are easy to flip.
* **PLECS PID anti-windup:** `aw_method = 1` → back-calculation (Kb = `kbc`), `3` → clamping.
  The output limits given in PLECS are applied. The derivative gain is zero in every
  controller used, so all of them are PI.
* **Periodic Average** = mean over the last completed period, held for the next period.
  **Moving Average** = sliding window.
* **PLECS sine sources** use Hz and degrees.
* **DAB load current source** draws power from the output (positive `Pout` = power to the
  load).
* **Filter inductor:** the SixSwitch filter inductor ("saturable" in the selected filter
  configuration) is linear, at its nominal `Lf`.

## Checking the translation

`tools/mock_simulink/` (Octave only — never put it on a MATLAB path, it shadows Simulink functions) is a stand-in for the Simulink API (`add_block`, `add_line`,
`set_param`, …) written in Octave. It:

* runs the build scripts unchanged;
* rejects unknown block paths, parameter names and enumeration values;
* checks that every port is wired and in range, and catches algebraic loops;
* then compiles the block graph into code and simulates it with a fixed step.

`tools/plant_checks/` holds open-loop checks of the plant equations.

```sh
cd tools/mock_simulink
octave-cli --eval "selftest"                      # the mock rejects bad models
octave-cli --eval "run_build_check('dab')"        # also 'classd', 'sixswitch'
octave-cli --eval "L = sim_check_dab(300e-6, 4e-9);"
```

Results of the check runs in the mock (fixed step 4–100 ns):

* **DAB, 4 ms:** ±700 V / ±250 V bridge voltages and the 5 % secondary zero state (αS = 0.025).
  The PI saturates at φ = 0.245 and delivers ≈ 2.5–3 kW, so Vo sags from 250 V to 238 V
  (see the leakage note above).
* **Class D, 567 Hz / 10 A demand:** the load current follows at ≈ 85 % amplitude. The
  bus settles at 401 V (zener plus 10 mΩ).
* **SixSwitch:** see the numbers above, for the saved selection and for `sel_q = 2`.

This is a strong check of the wiring and the arithmetic, but it is not MATLAB.

### Runs in MATLAB R2024b (2026-10-19)

All three models build, compile and simulate (`smoke_test`). Variable-step results
(ode23tb) agree with the mock:

| model, run | result | wall clock |
|---|---|---|
| DAB, 4 ms | bridges ±700 / ±250 V; secondary zero state ≈ 4 %; φ saturates at 0.2450; Pin ≈ 2.98 kW; Vo sags to 238.6 V (the load ramps towards `Pout`, ≈ 4 kW at 4 ms; the output capacitors make up the difference) | 6.5 s |
| Class D, 20 ms, `sel_ms = 2` | load current amplitude 8.9 A for 10 A demand (89 %); bus 401.4 V; leg currents up to ≈ ±22 A | 5.7 s |
| SixSwitch, 25 ms, as saved | Vdc peaks at 984 V at 3.9 ms, 699 V at 17 ms; idq = [9.0, −60.4] A at 25 ms | 3.7 s |
| SixSwitch, 25 ms, `sel_q = 2` | Vdc 700.0–700.1 V after 17 ms; idq ≈ [0.1, 0.2] A | 3.5 s |

Class D prints many "adaptive zero-crossing … below tolerance" warnings; they are harmless.
